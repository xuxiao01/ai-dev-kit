# 项目验证与本地验收

使用仓库自身的测试、配置和脚本证明本次改动，不能依赖作者电脑上的私有数据。无个人 Mock 时，公共验证流程仍完整可用；环境条件缺失时如实报告未验证，不伪装成通过。

## 按任务阅读

- 先读 [验证选择与结果交付](references/verification-guide.md)，按改动风险确定检查范围。
- 需要数据库、容器或浏览器验收时，再读 [本地环境与隔离](references/local-environments.md)，并核对当前配置。
- 用户要求 Mock 预览或已发现本地 Mock 时，才读 [可选 Mock](references/optional-mock.md)。不存在不影响核心验证，不要求创建或安装。

## 核心流程

1. 确认本次任务及 Git 改动范围，保留已有暂存和未暂存内容；不要把验证变成提交、格式化或业务改造。
2. 从当前仓库确认测试、依赖与命令，不仅凭历史记录操作。按风险选择最小充分检查，涉及共享行为时扩大回归范围。
3. 运行前确认依赖和环境目标；缺依赖、Docker 未运行、端口冲突或目标不明时，完成不依赖它的安全检查，再报告阻塞。不自动安装依赖、修改配置或切换用户的预览环境。
4. 后端功能测试与同库的性能／浏览器验收串行执行。先完成会清表的 pytest，再准备适用的模拟数据，不覆盖其他人的测试工作。
5. 区分单元测试、构建、服务可用和浏览器验收，交付实际结果及未覆盖项，不复用旧通过次数。

## 安全边界

- 测试仅指向本机已确认的独立测试库；库名正确并不足以证明安全，还需核对主机、端口、Compose 归属和用途。
- 不自动启用 `RUN_LIVE_TESTS`、真实行情、AI、SMTP 或交易；只使用适用测试桩及隔离数据。`paper` 模式不代表没有真实外部调用。
- 浏览器验收不对真实账户写入，不猜测密码或自动授予角色。真实邮件发送和其他外部动作需独立授权，不包含在普通验证中。
- 不清理他人服务、数据库卷或广泛资源；只处理本次创建且用途已确认的资源，复用资源默认保留。
- 无法证明隔离或只读保护时，停止有副作用的检查，记录原因；不绕过保护。分享结果时不输出凭证、完整私有配置或账户数据。

本 Skill 不自动串联 UI 设计、报告、提交或部署流程，也不授权补写测试、生成新场景或修改应用代码；需要时另行提出。
