# 本地环境与隔离

本指南只依赖仓库内配置，所有端口均为当前配置默认值，不是作者私有环境约定；运行前以实际配置和服务状态为准。缺依赖时报告准备条件，不自动安装、改端口或调整用户配置。

## 1. 环境用途

| 配置 | 用途与边界 |
| --- | --- |
| `compose.test.yaml` | 项目名 `multi-agent-investment-test`；`db-test` 为 PostgreSQL 16，数据库名 `multi_agent_investment_test`，默认仅映射本机 55432，数据在 tmpfs。用于可清空的测试，不保存日常数据。 |
| `compose.test.yaml` + `compose.perf.yaml` | 提供 `test-runner`（`tests` profile）、`api-perf`、`web-perf`；API/Web 默认本机端口 28102/23102，内部使用 `db-test`。用于容器化测试、分页性能及适用的隔离预览，不依赖个人 Mock。 |
| `compose.dev.yaml` | 独立日常开发栈，数据库使用持久卷，不是 pytest 测试库；不要合入上述组合或为验证清空。 |
| `compose.yaml` | 普通业务配置，不作为默认验证目标，不因目录里有 `.env` 就启动。 |

仓库还可能有其他 smoke 或故障预览配置。仅在目标任务适用、已读配置且确认隔离时使用，不把所有带 test/smoke 字样的环境等同于上述安全条件。

## 2. 运行前确认

- 确认当前仓库、Git 改动和依赖；只读检查 `docker info`、`docker compose ls` 和选定组合的 `ps`，核对服务、容器标签与占用端口，不先启动再判断。
- 阅读选定 Compose 文件及引用的覆盖配置。若需要解析配置，仅检查必要的服务、主机和端口，不把包含凭证的完整配置输出到交付内容。
- 测试库同时核对主机、端口、库名、Compose 归属与可丢弃用途；仅库名匹配不足以排除远程数据库风险。自动化测试会清表，复用正在被他人使用的测试库前需协调。
- 现有代码会读取环境配置；避免把私有 `.env` 或 SMTP 凭证挂入测试容器。pytest 的空密钥与网络桩不意味着启动 API 后也离线。
- 端口冲突、Docker 未运行、资源归属不明时停止相关步骤；不结束未知进程、不自动改端口、不覆盖配置。继续可独立完成的静态检查。

## 3. 代码新鲜度与 API/Web 预览

`Dockerfile.test` 和 API/Web 镜像包含构建时源码；perf API 仅额外挂载 `scripts`，不等于热加载所有后端改动。核对容器镜像、构建时间、挂载和实际启动配置；必要时说明需重建对应镜像，不只重启旧容器。

需要且已获准构建时，只构建相关服务。已有文档中的构建入口如下，不因存在此命令而在每次验证自动执行：

```sh
docker compose -f compose.test.yaml -f compose.perf.yaml --profile tests build test-runner
docker compose -f compose.test.yaml -f compose.perf.yaml build api-perf web-perf
```

功能测试结束、目标数据已准备且确认无真实外部调用风险后，才启动需要的预览服务：

```sh
docker compose -f compose.test.yaml -f compose.perf.yaml up -d api-perf web-perf
```

此组合关闭 SMTP 并留空模型／搜索密钥，但它**不是整套行情离线桩**。真实 HTTP 预览可验证本地接口与数据库，不应因此允许真实行情、AI 或邮件副作用；访问会触发外部调用的页面前，应先确认适用的现有故障桩／测试数据方案。缺乏条件则限制为可验证的页面或报告阻塞，不临时改业务代码绕过。

分页场景可按仓库分页文档使用受保护的既有数据脚本，账号和流程从文档核对，不依赖个人真实登录状态。其他页面没有现成数据或身份时，不声称已验收。

服务启动后分别检查健康状态、页面来源及目标请求。浏览器能打开并不证明页面包含最新代码、权限正确或全部数据已加载；Mock 响应也不等于真实后端响应。

## 4. 资源生命周期

- 开始时记下已存在资源和本次新建资源，只管理后者；复用容器不自动停止，已有测试数据不因验收便利重置。
- tmpfs 数据可在停止／重建测试数据库时丢失；结束前说明影响。有共享使用者时不停止 `db-test`。
- 确认仅停止本次创建的预览服务后，可用选定组合的 `stop api-perf web-perf`；不要对整组默认 `down`。测试库确属本次独占创建且允许丢弃时，再明确处理它。
- 不用 `down -v`、广泛 prune 或删除数据库卷；不操作日常开发库、远程服务、线上数据库或他人 Compose 项目。
