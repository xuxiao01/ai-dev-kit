# 可选 Mock 视觉验收

这一分支不是公共验证的前置条件。其他开发者没有个人 Mock 时，仍按 [验证指南](verification-guide.md) 和 [环境指南](local-environments.md) 执行仓库检查；不得要求复制作者私有文件。

## 发现与使用条件

- 仅查看当前仓库中是否存在 `local-mock/` 以及相应说明、场景清单、路由和启动配置；目录只是发现线索，不假定固定文件结构。不要扫描个人电脑寻找未知凭证。
- 若不存在或配置不完整，记录“可选 Mock 未使用”，继续公共流程，不下载、创建、复制、提交 Mock 或新增场景来凑验收。
- 从实际配置确认预览地址、代理目标、当前启用场景与接口作用域；不写死个人路径、端口、账户和场景名，不输出私有配置。
- 检查写请求是否阻断、未匹配接口是否透传、认证是否仍走真实后端。即使部分写请求被拦，也不能推断全部接口安全；未知时只查看，不执行保存、暂停、解散、发送等写动作。
- 不自动切换用户的场景、启停代理或改路由。需要改变预览状态时先说明影响并取得授权，结束时按约定恢复，不影响用户正在使用的环境。

## 能证明什么

适合检查长名称、多标的、多个状态、正负数值、缺失字段、空列表及失败展示。记录实际使用的场景及检查项，而非仅写“Mock 验收通过”。

不能证明数据库 LIMIT/OFFSET 性能、账户数据隔离、后端角色权限、SMTP 送达或真实行情供应商可用；这些使用仓库已有的隔离测试／真实本地接口方案。Mock 的 401/403 展示通过不代表服务端鉴权通过。

## 缺少场景时

现有仓库测试可验证部分状态逻辑，隔离 API/Web 可验证可用数据流程。它们不自动替代所有视觉场景：无法覆盖的明确标为未验收，不伪造截图或声称已覆盖，也不为验证任务自行补写场景。

公共结果与可选 Mock 结果分开记录。移除此文件及入口中的可选引用后，公共测试、构建与隔离环境指南仍可独立使用。
