# 项目 UI 风格

将本项目已确认的新版界面作为设计基线，不重新创造一套视觉系统。用户明确提出的设计要求优先；本 Skill 不授权扩展功能或改造无关页面。

## 按任务阅读

- 先按用户任务判断页面模式。设计新页面或重排布局时，阅读 [页面模式](references/page-patterns.md)，选择对象列表、信息详情、设置表单或数据总览；混合页面按主要任务组织，不强行套单一模板。
- 做视觉、布局或响应式设计前，阅读 [视觉与交互规范](references/visual-guidelines.md)。
- 修改实现或选择复用组件前，阅读 [组件与代码定位](references/component-guide.md)，再查看目标组件及调用方的当前代码。
- 只讨论方案时不修改代码；仅要求效果图时，不把示例数据或新增功能写进正式代码。

## 核心约束

- 延续浅色背景、单层白色卡片、轻边框、青绿色主操作和清晰信息层级。避免重复标题、厚重嵌套、渐变和无业务意义的装饰。
- 优先复用共享组件、语义字号和颜色 Token。Skill 只记录规则与定位，不复制 CSS 或维护第二套数值表。
- 以职责一致为复用前提。确有稳定布局差异时使用语义明确的 `variant`，不传页面名或任意样式对象集中所有差异，不为假想场景过度抽象。
- 局部改造默认放入 CSS Module；不顺带修改全局样式、导航、业务语义或权限。确需修改共享组件时，检查全部调用方并验证兼容性。
- 保留加载、失败、空数据、未登录和权限不足的区别。未知金额不显示为零，旧数据不表现为最新数据，权限不足不表现为未登录。
- 新增界面文案进入中英文词典，动态业务原文不强行翻译。错误不泄露凭证或内部响应；权限控制的诊断沿用现有后端鉴权。

## 工作与交付

1. 确认目标页面、用户任务及修改范围，检查账户状态、数据来源和组件调用关系。
2. 选择页面模式和最接近的新版参考，简要说明主要操作、信息层级及偏离推荐基线的必要理由；允许有理由的例外，不因统一风格改造所有页面。
3. 实施时保留接口、金额计算、业务操作、路由和刷新行为；未包含的业务变更单独提出。
4. 按风险验证中英文、长内容、移动端、键盘和数据状态。UI 代码变更使用项目现有验证流程；只整理文档或 Skill 时不运行应用测试。
5. 交付时说明范围、复用选择、已完成与未完成的验证，不把效果图当作真实接口或全部客户端验收。
