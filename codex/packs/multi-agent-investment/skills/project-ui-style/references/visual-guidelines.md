# 视觉与交互规范

## 1. 规范力度与事实来源

采用“统一基线，允许有理由的例外”。先按 [页面模式](page-patterns.md) 组织信息，再用本指南调整层级、间距和操作。

- **必须保留**：业务与数据含义、权限边界、可访问性、状态区别及用户明确要求。
- **推荐基线**：下面的尺寸、位置和密度是新设计的默认选择；内容需要时可调整，说明理由即可，不要求回改旧页面。
- **当前实现**：组件接口、Token 和具体数值以源码为准。现有页面并未全面统一；不要把建议写成已经实现的标准。

不复制整套 CSS，不新增间距 Token，不把所有页面强制变成同一种卡片布局。参考的是新版信息组织，不自动沿用参考页面中的历史装饰。

## 2. 视觉与信息层级

页面采用浅色中性底、白色内容表面、轻边框和适度圆角，不新增渐变、厚重阴影、装饰性指标或大面积品牌色。标题只显示一次，默认不添加重复的绿色 eyebrow。

| 信息职责 | 推荐排版角色 | 使用方式 |
| --- | --- | --- |
| 页面名称 | Page title | 复用 `PageHeader`，不在内容容器内重复同一名称。 |
| 业务区域 | Section title | 用于具有独立任务的区域，不给每个字段设大标题。 |
| 对象名称 | Card title | 默认卡片标题；现有突出对象名称的列表可保留 Section title。 |
| 正文、职责、解释 | Body | 主要说明保持可读，不将关键内容降为小字。 |
| 辅助标签、元信息 | Label | 用于版本、时间、字段标签等。 |
| 次要补充说明 | Caption | 不承载用户完成任务必须读清的关键操作或风险说明。 |
| 金额指标 | Metric | 使用现有 Metric Token 与等宽数字排布，保留币种、精度和正负号含义。 |

以上角色对应现有语义字号及行高 Token，见 [组件指南](component-guide.md)。不要靠连续放大标题制造层级。

- 主标题与关键值使用正常文本色；正文使用 `--ink` 或 `--ink-soft`，辅助信息使用 `--muted`。
- 品牌色用于操作和选中状态，不将所有标题染成绿色；收益、风险及运行状态使用已有语义色并配文字。
- 对象名称优先，其次是状态及关键摘要，最后是版本、时间等元信息。长名称允许换行，不挤没详情入口。
- 真实零值正常格式化；未知值显示现有“—”或“暂无数据”；旧数据保留时标记非最新。不能用视觉格式掩盖三者区别。

## 3. 间距、容器与密度

下表是推荐默认值，不是新增 Token，也不声称所有现有页面已经遵循。

| 场景 | 推荐基线 |
| --- | --- |
| 页面标题区到正文 | 24px |
| 主要业务区块之间 | 24px |
| 同类列表卡片之间 | 16px |
| 普通内容卡片内边距 | 桌面 24px，手机 20px |
| 紧密关联的信息 | 8px |
| 操作组内间距 | 12px |
| 表单字段或内部信息组 | 16～20px：同组紧凑字段优先 16px，独立设置组优先 20px |

- 保留页面外壳已有边距，不在每页重复增加外边距；外壳或共享组件已提供间距时，不再叠加同一份间距。
- 普通列表卡片参考 10px 圆角，设置分区参考 12px；现有共享组件、紧凑预览及浮层不强制迁移。
- 同页同类容器保持一致。分隔线表达实际分组，不给每个字段加框；一段相关信息优先靠对齐和间距组织。
- 列表对象优先独立卡片，不再套重复白色大卡片。详情可使用行与分隔线，表单可按任务分区，不将所有内容卡片化。
- 不设固定卡片高度裁掉正文，也不为视觉等高填充无业务意义的内容。屏幕密度由任务决定，不新增密度切换功能。

## 4. 操作层级与控件状态

- 页面头部默认突出一个主操作。对象列表通常是创建，设置页通常是保存；没有合适操作时不硬加按钮。详情跳转、刷新、测试发送按任务重要性使用次按钮或文字入口。
- 主操作使用纯色青绿，次操作使用轻边框或文字链接；危险操作使用克制的危险色。普通卡片详情入口在顶部操作区，业务操作与危险操作分组。
- 窄屏按阅读顺序排列：名称与状态、摘要、业务操作；详情入口可保留在名称之后，不为维持左右布局挤压正文。操作允许换行。
- 沿用已有危险操作确认机制，不因样式改造自行新增或取消确认，不把“查看详情”改成有副作用的动作。

| 控件状态 | 表达规则 |
| --- | --- |
| 默认 | 主次层级清楚，文字入口有可识别的操作文案及交互色，不伪装成普通正文。 |
| 悬停 | 使用现有色阶、背景或必要下划线反馈，不新增跳动、缩放等装饰效果；不将悬停作为唯一可发现线索。 |
| 焦点 | 保留清晰 `focus-visible` 或组件原生焦点，不移除轮廓而没有等效反馈。 |
| 禁用／只读 | 使用真实禁用或只读语义；需要解释时就近给出原因，不只变灰，也不只依赖悬停提示。 |
| 提交中 | 对应按钮显示进行中并防重复请求，不让无关区域全部进入 loading，也不丢失输入。 |

常用触摸入口以至少 44px 操作区域为目标，密集控件结合实际可用性处理。使用原生按钮和链接；展开及选中状态提供适合实际交互的 ARIA，不为普通列表滥用 `listbox/option`。

## 5. 加载、空数据与失败

| 状态 | 推荐呈现与边界 |
| --- | --- |
| 首次加载 | 保留标题及主要区域结构，用现有轻量占位或骨架，不闪现登录提示或虚构金额。 |
| 空列表 | 简述当前无数据，提供已有且有权限的下一步；不发明创建、导入等功能。 |
| 局部请求失败 | 在受影响区域说明并使用已有重试能力，其他成功区域继续显示；仅为视觉任务时不擅自改请求策略。 |
| 刷新失败但有旧数据 | 明示上次成功数据、当前更新失败；不伪造更新时间或最新估值。 |
| 确认未登录 | 使用共享登录提示，保留认证返回地址，不请求私有业务数据。 |
| 账户请求失败 | 展示账户错误及既有重试，不解释为未登录。 |
| 权限不足／只读 | 明确功能限制，禁用或保留现有只读操作，不显示登录卡片代替。 |

不强制全部状态使用同一组件。保存、测试邮件与规则操作等独立任务分别管理反馈；独立任务刷新不能覆盖未保存草稿。

公共错误只展示安全、可理解的原因，不暴露原始异常、供应商正文或凭证，不凭 HTTP 状态猜测供应商故障。诊断权限继续由后端确认，不因界面便利增加越权入口。

## 6. 响应式与文案

- 按内容空间减少列数，保持“名称／对象 → 关键内容 → 操作”的逻辑阅读顺序，不只靠 CSS 调换视觉位置。
- 使用可收缩网格、`min-width: 0` 和必要换行处理长名称、模型与正文；关键操作不被挤出。表格和标签可局部横向滚动，页面本身不得横向溢出。
- 列表、详情和表单不强制同一断点，按最窄可读列宽处理；文字省略仅用于非关键摘要，并提供现有完整内容入口，不裁掉必要信息。
- 新静态文案进入中英文词典，允许英文更长；名称、职责与指令等接口原文不改写含义。输入标签与单位明确，错误及风险说明不只靠颜色。

## 7. UI 改动验收建议

- 按涉及功能验证正常、加载、失败、空数据、未登录与权限受限状态，不为样式验收制造真实业务写操作。
- 检查中英文、长内容、缺失字段、375/768/1024/1440px、200% 缩放、键盘顺序和清晰焦点。
- 共享组件覆盖全部调用方，尤其完整详情和紧凑预览；未验证的环境明确说明。
- UI 代码变更运行相关现有测试、`web` 目录的 `npm run verify` 和 `git diff --check`。浏览器验收使用可用本地隔离环境，不擅自部署、发送邮件或修改真实账户。仅文档或 Skill 变更不运行应用测试。
